# 双 Agent 工作台整体升级实施说明

## 目标与状态

本轮升级保持“ChatGPT 规划与审查、DeepSeek 执行、Node.js 编排”的分工，集中完成协议可靠性、任务验证、失败回滚和 Dashboard 信息重构。v1.8、v1.9 与最小 v2.0 执行器扩展已合并在 v2.0.0 落地。

## 已实现范围

### 协议与重启恢复

- 新派发统一使用 v3 信封和唯一 `dispatch_id`。
- outbox 必须匹配 schema、派发、项目、任务和时间；拒绝重复、过期、半写与未知类型结果。
- 工作台 Skill 安装到独立 Harness Profile，不写入项目源码目录。
- 持久化 Harness 服务地址、进程、会话、cwd、任务、派发和会话代数。
- 重启后优先接管原会话；原任务仍在执行时只等待结果，不重复提交。
- 接管失败时生成 `executor_context.md`，先恢复检查点，再创建恢复执行。

### 任务与回滚

- 现有任务结构增加 `kind`、`validation`、`timeout` 和 `max_attempts`。
- 继续沿用任务数组与依赖关系，不增加工作流引擎。
- 内置编码、Bug 修复、分析和文档四种规划提示，由用户目标自动选择。
- 修改源码前创建任务检查点，排除 Git、依赖目录、构建产物、缓存和工作台目录。
- 失败、超时、服务崩溃、非法 outbox 或验证失败时先恢复再重试；恢复失败进入 `ERROR`。
- 成功并通过验证后清理临时检查点。

### Dashboard

- 保留双栏布局：左侧项目列表，右侧项目头、标签页、内容和固定 Composer。
- 顶栏只保留产品名、系统状态和主题切换；项目技术信息集中到“概览”。
- 暂停/继续保留在头部，重试、恢复、压缩、窗口、导出和结束收进更多操作。
- 统一 GPT、执行者、待处理和错误 Callout；任务表显示类型、执行、Token、验证与状态。
- 使用语义 CSS 令牌、4px 间距体系、本地 Lucide 图标和清晰键盘焦点。
- 标签页具备标准 ARIA 关系和方向键操作；状态同时显示文字与视觉标记。
- 700–1920px 保持无页面级横向溢出，窄屏任务表在内部滚动。

### 最小执行器扩展

- 执行器契约只保留执行、恢复、取消、用量、健康检查和 capability 信息。
- DeepSeek Harness 仍为默认实现；另提供一个配置式通用命令行执行器。
- Dashboard 根据 capability 隐藏模型、会话和窗口等无效控件。
- 审计导出直接汇总现有状态文件，不增加数据库、事件系统或插件注册中心。

## 保持不变

- 暂停、继续、结束、压缩、模型切换、附件和消息接口保持兼容。
- 旧项目在读取时惰性补默认值，不做批量迁移。
- 不引入 React、Vue、Tailwind、Ant Design、YAML 工作流、模板市场、移动端、三栏检查器、外部数据库或复杂动画。

## 验收

- `npm test` 覆盖协议、依赖调度、验证重试、检查点恢复及恢复失败停机。
- `node test/verify-task009.mjs` 覆盖主要操作、标签页、Composer、主题和 1920、1440、1280、900、700px 布局。
