# 双 Agent 工作台完整演进路线图

## 总结

分四个独立版本推进：先解决成本与上下文增长，再强化协议和恢复能力，随后加入自动回滚与操作界面，最后建设模型推荐、任务模板和执行器扩展。每个版本均可单独上线、回归和回退。

## 分阶段实施

### v1.7：成本可观测与上下文控制

- 每次 DeepSeek 任务执行前后读取 Harness `session.history` 的 `tokenUsage` 投影，记录真实输入、输出、缓存读写、上下文压力和窗口容量；GPT 因网页端无真实用量，只记录字符数和明确标记为“估算”的 token。
- 在项目状态增加逐任务和累计用量，Dashboard 展示模型、推理等级、耗时、重试、token、上下文占用百分比。
- 上下文达到窗口的 70% 时自动压缩；投影不可用时以同一会话完成 20 个任务为后备阈值。
- 压缩时根据计划、完成/失败任务、决策和近期报告生成 `executor_context.md`，创建新 Harness 会话，重新加载 Skill 和摘要，不重发完整历史，也不重新打开窗口。
- 增加“压缩会话”按钮；执行中点击则登记为待处理，在当前任务结束后执行。
- 项目中途切换模型时不打断当前任务；任务结束后让 GPT 仅重写未完成任务，随后用新模型建立摘要化会话。空闲状态切换则立即执行增量重规划。

### v1.8：协议隔离与断点恢复

- 将 `workbench-executor` 从项目 `.dsh/skills` 移到工作台专用 Harness Profile 的私有 Skill 根；项目和普通 DeepSeek 会话不再发现该 Skill。
- 升级任务信封为 v3，每次派发生成唯一 `dispatch_id`；outbox 必须回传相同 ID，并校验类型、任务 ID和必填字段。
- DeepSeek 先写临时 outbox，再原子重命名；编排器拒绝半写、过期、重复或未知类型的结果。
- 对旧项目做惰性迁移：旧信封仍可完成当前任务，新派发统一使用 v3；只删除内容仍与工作台托管版本一致的旧 Skill 副本，用户修改过的副本保留并警告。
- 持久化 Harness 服务端口、Profile、cwd、sessionId 和会话代数。工作台重启后先验证服务身份、目录和会话，再重新接管；无法接管时使用现有项目摘要建立新会话。
- 已接管会话不重复开窗；若重启时任务仍运行，继续等待原 outbox，不重复派发。

### v1.9：自动恢复与任务操作界面

- 每个任务开始前创建文件检查点，排除 `.git`、依赖目录、构建缓存和工作台目录；默认最大 512MB，可配置。
- `TASK_FAILED`、超时、执行服务崩溃或无合法 outbox 时，先自动恢复到任务前检查点，再进入现有重试流程；恢复失败则进入 `ERROR`，禁止在不确定文件状态下继续。
- `TASK_DONE` 且报告校验通过后清理检查点；项目保留最近一次成功任务的恢复信息。
- Dashboard 增加任务依赖图、阻塞原因、执行次数、实际模型、上下文压力和检查点状态。
- 增加“重试当前任务”“跳过并询问 GPT”“立即压缩”“恢复最近检查点”操作；所有操作继续走项目 epoch 防止迟到结果覆盖。
- 最终报告加入用量汇总、模型变更、压缩次数、重试、自动回滚、未解决风险和测试结果。

### v2.0：自适应与可扩展能力

- GPT 任务结构新增可选 `kind` 和 `complexity`，用于区分编码、测试、分析、文档和运维任务，以及低/中/高复杂度。
- 本地汇总各模型在相同任务类别上的成功率、重试率、耗时和 token；样本少于 5 次不推荐，达到样本量后只在 Dashboard 提示更合适的模型，不自动切换。
- 增加编码、Bug 修复、项目分析、文档四种内置计划模板；默认自动选择，创建项目时允许覆盖。
- 抽出执行器适配契约：任务信封、结果信封、模型目录、会话状态和可见界面均通过 capability 声明。DeepSeek 保持默认适配器，同时提供可配置的通用命令行适配器；不支持某能力时界面自动隐藏对应控件。
- 增加本地审计导出：生成带 manifest 的目录，包含计划、任务报告、决策、用量、测试、模型变化、压缩记录和最终报告，不引入压缩依赖。

## 接口与数据变化

- 项目状态 schema 升级，新增 `usage`、`session_generations`、`pending_model_replan`、`checkpoint`、`model_recommendations`；读取旧状态时自动补默认值，不批量改写现有项目。
- 项目详情 API 返回用量、上下文压力、压缩状态、检查点和推荐信息。
- 项目操作 API 新增 `compact_session`、`retry_task`、`skip_and_ask_gpt`、`restore_checkpoint`、`export_audit`。
- 配置新增上下文阈值、后备任务数、检查点开关/容量/排除目录以及通用执行器清单；缺省配置保持当前 DeepSeek 工作流可运行。

## 测试与验收

- Token 投影存在、缺失、重启后累计、会话切换后分代统计均正确，估算值与真实值明确区分。
- 自动和手动压缩都只建立一个新会话，摘要包含继续执行所需状态，不重复执行已完成任务。
- 模型在运行中和空闲时切换均只重规划未完成任务，不中断或重复当前任务。
- 普通 DeepSeek 会话无法发现工作台 Skill；工作台 Profile 可以稳定加载。
- 过期、半写、错误任务 ID 和重复 outbox 均被拒绝，旧信封迁移可继续完成。
- 工作台重启后能接管仍存活的服务；失效服务使用摘要恢复且不丢失项目进度。
- 失败任务自动回滚新建、修改和删除的文件；超过容量、恢复失败和外部并发修改时安全停机。
- Dashboard 各新增操作具备状态机、暂停、删除和迟到结果回归测试；每阶段运行 `npm test` 与综合 UI 回归。
- 每个版本独立更新 README、版本号、CHANGELOG 索引，并新建符合项目规则的版本日志。

## 已锁定的默认决策

- 分阶段发布，不做单一大版本。
- 上下文压缩采用自动阈值加手动入口。
- 工作台保持完全无人值守，不增加危险操作审批。
- 任务失败默认自动回滚本任务。
- 模型推荐只提示，不自动切换。
- 不纳入多任务并行执行。
- 所有统计和审计数据仅保存在本机，不上传外部服务。
- 保留当前未提交改动和项目运行数据，不清理、不覆盖无关文件。
