# v2.0.6 — GPT 内置规范附件与跨目录加载核验

- 日期：2026-09-04
- 版本：2.0.6

## 改了什么

- 将 GPT 固定角色、通信协议与规划规范从代码长字符串迁移到 `docs/gpt-workbench-rules.md`，按程序位置读取，不受启动目录或项目目录影响。
- 新 GPT 会话把规范与当前指挥档规则合为 Markdown 附件，与用户文件一起发送；正文只保留任务、阅读入口和简短模型/协议提醒。
- 以文档和当前规则的内容摘要记录已发送版本。恢复同一会话不重复上传；新会话、旧项目缺少记录、规范更新或有效模型档位变化时自动补发。发送失败或被暂停后不记为已发送。
- 规范快照与发送记录保存在项目工作区，源码目录不新增规则文件。内置附件字符数计入 GPT 字符/token 粗略估算，避免把文件形式误报为零上下文消耗。
- README 解释 GPT 上传机制、DeepSeek 专用 Profile 与外部源码目录的关系；区分工作台执行协议和维护工作台自身的 AGENTS.md。
- 新增规范初始化、恢复、项目隔离、档位更新、失败重试、附件用量及隔离 Chrome 附件入口回归。

## 为什么

原实现每个 GPT 会话首条内嵌完整角色和协议，多种后续消息还会重复追加长篇指挥规则。将固定规则集中维护、只在新会话或规则变化时发送，能减少重复消息内容并方便更新。文件被模型读取仍占上下文，不能把附件化当作免费记忆。

DeepSeek 原有实现已将规则作为专用 Profile 的 bundled Skill 提供，适用于工作台管理的所有源码目录，无须改成每项目复制。规范加载取决于启动进程的配置，不取决于源码是否在工作台的子目录。

## 验证

- `npm test`：核心回归、协议、GPT Mock 与中文路径自测通过，包含新增规范机制和隔离 Chrome 附件上传验证。
- 使用本机实际安装的 DeepSeek Harness `FileSystemSkillProvider`：默认源码目录与外部中文源码目录都能发现并读取 `workbench-executor`；去除工作台 bundled Skill 环境后，隔离的普通会话无法发现该规范。
- 未改动 Dashboard，无需额外界面回归；未向真实 ChatGPT 账号发送测试消息，也未调用 DeepSeek 模型。网页端是否正确理解文件未做真实模型验收；现有计划/协议校验继续兜底。
