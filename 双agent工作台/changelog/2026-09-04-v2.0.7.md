# v2.0.7 · Windows 可移植安装

日期：2026-09-04

## 改了什么

- 修改前保存源码备份 commit `68d0caa`。
- 仓库根目录提供 npm 安装、启动、模拟体验、自检与测试入口，统一锁文件和公开 npm 下载地址；添加 Windows Node.js 22/24 CI。
- 移除固定用户名和执行器位置，自动发现当前 Windows 的浏览器与 Harness；保留环境变量和本机配置覆盖。
- 默认配置与 `config.local.json` 分离，启动参数和相对路径统一解析；默认不要求指定的 ChatGPT 订阅模型。
- Windows 启动器透传参数、检查依赖并打开实际配置端口，计划任务记录当前 Node 可执行文件位置。
- 默认源码目录随项目位置解析；外部源码路径失效时提示重选，阻止在错误目录继续执行。
- 浏览器登录态、运行日志、个人项目与 node_modules 退出版本跟踪，本机文件保留。旧提交历史未重写。
- 浏览器回归测试自动发现本机浏览器，个人样例不再作为新用户依赖；自测使用临时目录。
- 更新安装、配置、迁移与故障排查文档。本次范围仅 Windows，不扩展 macOS/Linux。

## 为什么

原配置绑定作者的 Windows 用户目录，仓库混入本机运行数据，根目录缺少安装入口。新用户即使拉取源码也难以按原说明运行。本次让依赖发现、配置与数据归属跟随使用者的机器。

## 验证

- Windows / Node.js 24.16.0：`npm test` 通过（89 项核心回归、21 项可移植性回归，协议 23、GPT 桥 7、目录选择 4 项自测）。
- `npm run test:ui`：50/50 通过，无 JavaScript 错误；浏览器性能测试通过。
- 将源码单独导出到全新中文、空格路径，未复制个人配置、浏览器状态、项目数据或旧 node_modules；在仓库根目录和应用目录执行 `npm ci` 均成功。
- 新目录下模拟闭环完成三项任务及最终审查；从其他工作目录调用根目录 `start.bat` 成功；自定义端口/数据目录启动 HTTP Dashboard，项目列表为空。
- 已安装的 Harness 0.1.1-rc.2 在全新临时 `DSH_HOME` 下，Web/headless 配置初始化成功，真实 Web 服务约 1 秒就绪；随后关闭并清理，未调用模型。
- CI 配置包含 Windows Node.js 22/24，远程工作流尚未运行。真实 ChatGPT/模型端到端调用未重测，仍需使用者自己的账号、网络和模型配置。
