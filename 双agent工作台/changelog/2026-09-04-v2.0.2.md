# v2.0.2 — Harness 官方工作区归属修复

日期：2026-09-04

## 改了什么

- 新建和压缩会话先注册/复用实际源码目录对应的官方工作区，再通过 workspaceId 创建会话。
- 复用和重启接管时，使用官方同 ID 幂等创建为旧会话补关联；核对实际 cwd，不把父目录会话错误归入子项目。
- 默认源码目录名称为 source 时，以项目名命名新工作区；已有自定义标题不覆盖。
- 工作区注册/补关联失败明确报错，不静默降级为未分组的 headless 执行。
- 通过 3080 官方服务，将贪吃蛇的两条既有会话归入“贪吃蛇速度验收”；未改会话 ID、未重做任务、未删除消息历史。官方加载被中断旧会话时补写了生命周期结束事件。

## 为什么

旧实现仅调用 session.create({cwd})。Harness 明确将该路径创建的会话视为未分组；目录相同或位于父工作区内都不会自动建立成员关系。官方工作区要求规范化后的 cwd 与工作区路径完全一致，并且 sessionIds 中有该会话。

## 验证

- npm test：57 项核心/分组回归、23 项协议、7 项桥自测、4 项路径检查全部通过。
- 新增分组回归覆盖新建、复用、压缩、旧会话补关联、标题保护、重启接管、目录不匹配和注册失败。
- 真实 3080 workspace.list 已包含两条既有贪吃蛇会话；浏览器已确认“贪吃蛇速度验收”分组可见。
- 本次未修改工作台 Dashboard，无需新增 Dashboard 行为测试；没有改动 Harness 安装包或直接编辑其注册数据。
