# v2.0.0 — 协议恢复、任务验证与工作台 UI

日期：2026-09-03

## 主要更新

- 执行信封升级到 v3，以 `dispatch_id`、项目 ID、任务 ID 和时间戳校验结果；拒绝重复、过期、半写、未知类型和错配结果。
- DeepSeek 结果改为临时文件写完后原子重命名，工作台专用 Skill 移到独立 Harness Profile。
- 持久化 Harness 服务、会话、工作目录和会话代数；工作台重启后优先接管原任务并只等待原结果。
- 任务支持 `kind`、`validation`、`timeout` 与 `max_attempts`，并提供编码、Bug 修复、分析、文档四类规划提示。
- 修改源码前建立任务检查点；任务失败、超时、执行服务崩溃、非法结果或验证失败时先恢复再重试，恢复失败立即进入 `ERROR`。
- 增加重试当前任务、恢复最近检查点和导出审计记录接口。
- 增加最小通用命令行执行器，并通过 capability 字段控制 Dashboard 中不可用的选项；DeepSeek 仍为默认执行器。
- Dashboard 改为紧凑双栏开发者工作台：技术信息归入概览，项目操作收进菜单，统一状态提示、任务验证列、文本阅读和固定 Composer。
- 引入语义 CSS 令牌和本地 Lucide 图标，补齐标签页键盘操作、焦点样式、文字状态与 700–1920px 响应式布局。

## 兼容性

- 项目状态在读取时惰性补齐 schema 3 默认值，不批量改写旧项目。
- 现有暂停、继续、结束、压缩、模型切换、附件和消息接口保持不变。
- 通用命令行执行器默认未配置，不影响现有 DeepSeek 项目。
