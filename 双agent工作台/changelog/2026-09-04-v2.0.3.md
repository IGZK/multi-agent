# v2.0.3 — GPT 窗口复用与程序化任务拆分

- 日期：2026-09-04
- 版本：2.0.3

## 改了什么

1. 移除 GPT Chrome 启动时的 `about:blank` 和 `--restore-last-session=false`；使用 `--no-startup-window`，连接后选择已有 ChatGPT 页面或创建一个工作页。并发唤起共享启动/连接，失败后 60 秒内不重复启动；连接断开优先重连。空白页导航失败会关闭该页，不遗留空白窗口。
2. 清理空白页前通过 CDP 验证工作台专用 Profile，只关闭没有内容的 `about:blank`；其他网页及有内容的空白页保留。没有所有权证据时不清理。
3. 新增 `controller/planning_policy.mjs`，集中定义 V4 Flash、Flash Vision Exp、Pro × off/low/high/max 的任务预算。所有档位均要求具体文件、3 条以上步骤、1–2 个交付物、待决策数组、依赖、验收和失败处理；默认或未知档位采用保守预算。提示与实际校验共用规则，取消固定 2–4 项的任务总数要求。
4. GPT 新计划使用 JSON，旧计划仍可读取；计划保存前及未完成任务执行前校验字段、粒度、唯一 ID 与依赖图。错误反馈给 GPT，默认最多自动修正两次；超限停在 ERROR，不能以 CONTINUE/DONE 绕过。有效计划不会被无效回复覆盖，校验结果及版本保存到 `planning_check` 并包含在审计导出中。
5. 增量重规划保留完成记录和已完成任务原契约，修正过的失败任务重新进入可执行队列；恢复执行时采用当前计划中的契约。暂停期间迟到回复不会重新触发派发。
6. 规划与执行按相同规则合并项目选择和全局默认。真实派发前依据 Harness 报告的档位复查预算；模型选择失败或预算不符不会静默回退到其他执行方式。指定模型无法在 headless 回退中保证时停止派发。
7. 更新 README、Mock 计划、回归测试及包版本，不增加依赖。

## 为什么

- Chrome 的恢复开关按“是否存在”判断，写成 `=false` 仍会恢复历史会话；叠加空白启动页会积累窗口。[Chromium 源码](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/ui/startup/startup_browser_creator.cc)
- 原实现仅把“强模型任务粗、弱模型任务细”写进提示，没有明确输入格式、档位预算和拒绝机制；计划遗漏细节也会直接执行。
- 任务预算是本项目的保守工程规则，并非官方能力上限。思考模式参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)；目标覆盖和步骤语义仍需 GPT 审查，程序负责结构及数量约束。

## 验证

- `npm test`：核心及新增回归、协议、GPT Mock、文件夹选择器测试通过。
- 新增隔离真实 Chrome 测试：并发唤起、空白页清理、非工作页保护、导航失败、页面关闭后重建、CDP 断线重连。测试使用临时 Profile 和本地网页、无头模式，不使用真实账号。
- 新增规划测试：所有模型/档位预算、默认值合并、JSON 与旧计划、字段与依赖校验、修正上限、拒绝绕过、降档复检、增量完成保护、失败任务恢复、暂停竞态、禁止备用路径绕过、实际低档位拒绝、完整 Mock 协作闭环。
- 本次未改 Dashboard 页面，不涉及 UI 回归门槛。未进行真实 GPT/DeepSeek 付费调用；未手动修改浏览器登录态、运行日志或已有项目数据。

## 生效

下次启动工作台即加载新逻辑。已完成项目保持记录；旧项目的未完成计划在继续执行前自动进入补齐和校验流程。
