# v2.0.1 — 本地链路提速与真实贪吃蛇验收

日期：2026-09-04

## 改了什么

- 启动不再固定等待四秒；GPT 空闲预热、连接去重、空白会话复用，避免重复导航。恢复中项目不并发预热抢占页面。
- GPT 文本填入、发送确认、会话恢复改用就绪条件；回复检测默认 300ms，停止生成且文本稳定 500ms 才接收。后台 Chrome 禁用后台计时节流；旧会话残留或导航失败时拒绝误发。
- 状态推进后立即继续；DeepSeek 服务提前预热，模型配置缓存，投影并行短超时；outbox 用文件事件唤醒 + 150ms 兜底，诊断 RPC 不阻塞收包。恢复收包同样支持即时唤醒。
- Dashboard 请求防重入、详情响应防串项目、模型目录按需加载；UI 回归有失败时返回非零退出码。
- 检查点异步复制且排除运行数据，增加暂停/删除期间不派发的保护。
- 区分命令验证和自然语言验收；小项目按 2–4 个端到端任务规划，减少无意义往返。
- 实测发现执行者把北京时间标为 UTC 导致结果拒收：补充程序化 UTC 指引，并对身份匹配、仅时间无效的结果最多请求一次重发，不直接回滚已完成的代码。
- 过滤已完成派发的迟到重复结果，防止上一任务补写 outbox 导致下一任务误回滚；成功后清理同任务未解决失败标记，避免同时显示成功与失败（历史日志仍保留）。
- 补充性能、协议修复、检查点安全和会话导航回归测试；无新增依赖。

## 为什么

原路径存在重复页面加载、累计秒级固定等待、串行探测和两秒收包轮询。自然语言验收误执行、时区错误结果被拒收还会触发整项重做，放大总耗时。优化保留登录、生成完成、派发身份和暂停/删除校验，不通过跳过验证来提速。

## 验证与测量

- `npm test`：53 项核心 + 23 项协议 + 7 项桥自测 + 4 项路径检查，全部通过。Dashboard 50/50 通过；隔离 Chrome 性能/流式保护测试通过；mock 全闭环约 3 秒完成。
- 隔离 DOM：空白页复用+发送 154ms；已完整生成的回复收包 544ms。DeepSeek 人工卡住健康/会话 RPC 时，25ms 后写入的结果约 33–36ms 内被收到。
- 真实首轮：后台开始到 GPT 已登录约 1.9s；项目创建到消息确认 8.0s；GPT 计划收到到 DeepSeek 提交约 0.19s。上次日志创建到消息确认约 91.5s；不同网络/页面状态，不视作严格等条件基准。
- 真实样例：`projects/2026-09-04-贪吃蛇速度验收/source`。GPT 规划 → 两项 DeepSeek 任务 → 分析 → GPT 判定完成已跑通；样例 `node --test` 10/10 通过，浏览器 11 项交互/离线检查通过，直接打开加载实测 47–95ms。测试过程中确实触发了时区错误、旧结果补写与运行进程中断恢复；不把这次含故障注入的总耗时当作纯速度基准。
- 模型服务端生成与网络耗时不受本地优化保证；本次网页未确认 GPT-5.6 Sol，日志明确记录使用页面默认模型。

浏览器登录资料、运行日志和既有项目数据未手工编辑或纳入代码变更；运行测试产生的浏览器/项目状态保留在本机。
