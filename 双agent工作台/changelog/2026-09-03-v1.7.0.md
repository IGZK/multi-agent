# v1.7.0 · 成本可观测与上下文控制

日期：2026-09-03

## 改了什么

- 每次 DeepSeek 会话池任务前后读取 Harness `session.history` 的 `tokenUsage` 与 `contextPressure` 投影，按任务记录真实输入、输出、缓存读写、实际模型、推理等级、耗时、重试和上下文占用，并跨会话代数累计。
- GPT 网页消息记录字符数和约 4 字符/token 的估算值，所有状态与界面均明确标为“估算”，不冒充真实用量。
- 项目状态升级为 schema 2，新增 `usage`、`session_generations`、`pending_model_replan`、`compaction` 以及后续版本预留的检查点/推荐默认字段；旧项目读取时惰性补默认值，不批量改写。
- 上下文达到 70% 时自动生成 `executor_context.md` 并在同一 Harness 服务内创建一个摘要化新会话；投影不可用时，同会话完成 20 项任务触发后备压缩。新会话下一任务重新加载 Skill 和摘要，不重发旧历史、不重开窗口。
- Dashboard 新增“压缩会话”按钮；执行中点击只排队，在任务结束后处理。项目详情和任务表新增累计/逐任务用量、模型、推理等级、耗时、重试及上下文压力。
- 模型切换在当前任务运行时只登记，不取消任务；任务结束后 GPT 仅重写未完成任务，再创建应用新模型的摘要化会话。空闲切换会立即进入增量重规划。
- 保存完整的 v1.7–v2.0 演进路线图到 `docs/双-Agent-工作台完整演进路线图.md`。

## 为什么

长期复用执行会话会让上下文和成本持续增长。v1.7 先把真实用量、压力和会话代数变成可审计状态，再用摘要化换代限制上下文，同时保证模型切换不打断或重复当前任务。
